# KOMPAS-3D MCP

Локальный MCP-сервер, через который AI-агент управляет **КОМПАС-3D на Windows**: строит детали и чертежи, проверяет геометрию и экспортирует файлы. Подключается к установленному КОМПАС через официальные COM API5/API7.

**76 инструментов · Python 3.13 · MCP stdio · Windows**

> Это экспериментальный инструмент автоматизации, а не замена проверки инженером. Сервер работает с настоящими документами КОМПАС; перед использованием на важных файлах сделайте резервные копии. Наблюдались падения самого КОМПАС — ограничения описаны в [STABILITY.md](STABILITY.md).

## Что умеет текущая версия

| Направление | Возможности |
|---|---|
| 2D | Отрезки, окружности, дуги, прямоугольники, ломаные, текст, слои, DXF |
| 3D | Эскизы, замкнутые контуры из линий/дуг/окружностей, выдавливание, вращение, вырезы, фаски и скругления |
| Проверка модели | Число тел, твёрдость, габариты, объём, ошибки построения, поиск граней и рёбер |
| Координаты | Фактические оси эскиза, преобразование локальных/мировых координат, явное направление операций |
| Чертежи | Ассоциативные виды модели, заданная ориентация, линейные/радиальные/диаметральные размеры, основная надпись |
| Сборки | Добавление компонентов, дерево сборки, положение и ориентация компонентов |
| Вывод | Нативное сохранение, STEP/STL/IGES/Parasolid, PDF, PNG/JPEG, снимки окна |
| API | Каталог установленного SDK, описание COM-объектов, публичные get/set/call/cast без `eval` |

Сопряжения сборок, сложные сечения и полный цикл производственного оформления **не заявлены как готовые проверенные сценарии**. Четвертной вырез на изометрии через временное изменение модели пока не завершён как надёжный workflow. Подробности: [COVERAGE.md](COVERAGE.md), [TOOLS.md](TOOLS.md).

## Требования

- Windows и установленный КОМПАС-3D с зарегистрированными COM API.
- **Обычный Windows Python 3.13**, не Python из MSYS2. Проверенная CAD-среда: КОМПАС-3D v25 Учебная версия; совместимость с другими версиями не гарантируется.
- MCP-клиент, поддерживающий запуск локального сервера через stdio, например OpenCode V2.
- Для снимков окно КОМПАС должно быть развёрнуто, не свёрнуто. Ограничения лицензии КОМПАС распространяются и на автоматизацию/экспорт.

## Быстрый старт

В PowerShell:

```powershell
git clone https://github.com/noki1928/kompas-mcp.git
cd kompas-mcp
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если `py` не установлен, создайте окружение полным путём к вашему Windows `python.exe`. После этого все команды запускайте через `.\.venv\Scripts\python.exe`.

Для проверки запуска:

```powershell
.\.venv\Scripts\python.exe server.py
```

Сервер ожидает MCP-сообщения на stdin — **отсутствие обычного вывода нормально**. Это не интерактивная консоль. Остановить ручной запуск можно `Ctrl+C`; при работе через клиент запуском управляет сам клиент.

### Подключение к OpenCode V2

Скопируйте [opencode.example.json](opencode.example.json) в `opencode.json` в корне проекта:

```powershell
Copy-Item opencode.example.json opencode.json
```

Пример использует относительные пути и запускается из этого проекта:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "kompas": {
        "type": "local",
        "command": [".venv/Scripts/python.exe", "server.py"],
        "cwd": ".",
        "environment": {"KOMPAS_ALLOW_SCRIPTS": "0"}
      }
    }
  }
}
```

В V2 серверы находятся в **`mcp.servers`**. Для глобального подключения или запуска из другого проекта задайте абсолютные пути к Python, `server.py` и рабочему каталогу.

```powershell
opencode mcp list
```

В OpenCode используйте `/mcps` для проверки и переподключения сервера. После изменения исходников/схем инструментов переподключите `kompas`: процесс не перезагружает код автоматически. Документация клиента: [OpenCode V2 MCP](https://opencode.ai/v2/docs/mcp-servers).

## Первый запрос агенту

> Создай новую деталь: пластину 100×50×12 мм со сквозным отверстием Ø10 в точке (25,25). Проверь одно твёрдое тело, габариты и объём. Сохрани в новый M3D-файл и покажи модель. Не изменяй открытые документы.

Рекомендуемый порядок вызовов:

1. `status` / `get_kompas_state` — проверить подключение и открытые документы.
2. `create_document(kind="part")` — создать отдельную деталь.
3. `sketch3d(plane="XY", rectangles=[[0,0,100,50]])` — профиль основания.
4. `extrude(sketch_id=..., depth=12, direction=[0,0,1])` — основание.
5. `sketch3d(plane="XY", circles=[[25,25,5]])` — профиль отверстия.
6. `cut_through_all(sketch_id=..., direction=[0,0,1])` — сквозной вырез.
7. `check_model_contract(expected={"body_count":1,"bounds_mm":[0,0,0,100,50,12],"volume_mm3":59057.52220392306})`.
8. `save_document(path="C:/your/output/plate.m3d")` — новый путь, не существующий файл.

Это последовательность **MCP-вызовов**, не готовый Python-скрипт. ID берутся из предыдущих ответов.

Для сложных контуров и плоскостей XZ/YZ используйте `create_closed_profile` с явными осями либо `get_sketch_frame` и `transform_sketch_points`. Нельзя угадывать знаки локальных координат по названию плоскости. Подробные схемы: [EXPLICIT_GEOMETRY.md](EXPLICIT_GEOMETRY.md).

### Важные правила работы

- Длины — мм, углы — градусы. Координаты эскиза и аннотаций чертежа локальные; положение вида задаётся на листе.
- `extrude` по умолчанию требует **одно твёрдое тело**. Для намеренного многотельного результата задайте `result_mode="auto"` или `"new_body"`.
- Любая ошибка любого инструмента приходит как MCP `isError` с JSON `success=false` (в `structuredContent` и в тексте). У неудачной операции изучайте `failures` и `cleanup`; удаление нового элемента не является универсальным откатом.
- ID объектов действуют только в своём документе и процессе MCP. После перестроения заново получите ID граней, рёбер и тел.
- Завершайте `end_sketch_edit` перед построением операций, сохранением и переключением документа.
- Виды на чертеже связаны с моделью; временная правка модели может затронуть несколько видов. Не полагайтесь на изолированное перестроение без проверки.
- Размеры по координатам создаются настоящими объектами КОМПАС, но не привязаны автоматически к рёбрам модели. Материал, допуски и производственная пригодность требуют отдельной проверки.

## Безопасность и настройки

Скрипты **отключены по умолчанию**. Большинство сценариев не требует их включения.

| Переменная | Назначение |
|---|---|
| `KOMPAS_ALLOW_SCRIPTS=1` | Разрешает `execute_python_script`: произвольный Python с полными правами пользователя, **не песочница** |
| `KOMPAS_LOG_PATH` | Путь к журналу действий; по умолчанию `artifacts/actions.jsonl` |
| `KOMPAS_DEBUG=1` | Включает запись текста исполняемых скриптов в журнал |

Универсальный COM-доступ также не является песочницей. `allow_mutation=true` обозначает разрешение на конкретный вызов, но не гарантирует безопасность произвольного SDK-метода.

Сохранение/экспорт защищают существующие пути по умолчанию. Контрольные точки создают отдельную рабочую копию через SaveAs и меняют текущую файловую привязку; зависимости сборки не снимкуются. Нет жёсткой отмены зависшего COM-вызова и автоматического повторения мутаций после сбоя.

Журнал может содержать пути и геометрию; автоматическая ротация не реализована. Локальные конфиги, CAD-файлы, SDK-снимки, журналы и исследовательские `probe*.py` исключены из Git.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Один тест:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_geometry.py" -k test_frames_roundtrip_all_planes -v
```

### Живые MCP-регрессии

С установленным КОМПАС и развёрнутым окном выполняйте **строго последовательно**:

```powershell
.\.venv\Scripts\python.exe tests/smoke_explicit_geometry.py
.\.venv\Scripts\python.exe tests/smoke_extended.py
.\.venv\Scripts\python.exe tests/smoke_stability.py
```

Они запускают собственные MCP-процессы со скриптами, отключёнными через `KOMPAS_ALLOW_SCRIPTS=0`, но используют одну CAD-сессию. Не запускайте одновременно другие CAD-вызовы и не проводите регрессию при наличии незаменимой несохранённой работы.

Тесты создают отдельные документы и каталоги `artifacts/<run>/`. **Только `passed.json` означает полное завершение**; отдельные PASS-строки не доказывают успех всего прогона.

Ранее на этой версии завершены три живых прогона: **271 MCP-вызов, все 76 имён инструментов**, включая ожидаемые отказы. Это не покрытие всех комбинаций параметров. Подробные результаты и неудачные попытки: [COVERAGE.md](COVERAGE.md), [STABILITY.md](STABILITY.md). Локальные отчёты не входят в репозиторий; повторите проверки в своей CAD-среде. При подготовке публикации повторены unit-тесты, живые прогоны заново не запускались.

## Разработка и документация

`server.py` и `extended_tools.py` регистрируют MCP-инструменты. `ComWorker` в `kompas.py` выполняет все COM-вызовы последовательно на одном STA-потоке. COM-объекты нельзя переносить в обработчики MCP/другие потоки: наружу возвращаются JSON и registry handles.

- [AGENTS.md](AGENTS.md) — краткие инструкции для следующих агентских сессий.
- [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md) — безопасный порядок CAD-операций.
- [ARCHITECTURE.md](ARCHITECTURE.md) — устройство сервера и границы модулей.
- [TOOLS.md](TOOLS.md) — каталог инструментов; точные схемы доступны через MCP `list_tools`.
- [EXPLICIT_GEOMETRY.md](EXPLICIT_GEOMETRY.md) — контуры, оси и контракты результата.
- [COVERAGE.md](COVERAGE.md) / [STABILITY.md](STABILITY.md) — проверенное покрытие и ограничения.
- [VALIDATION.md](VALIDATION.md) — история ранних проверок, не актуальный итог покрытия.

Проверяйте сигнатуры и enum в установленном SDK, а не угадывайте их. Для локального аудита:

```powershell
.\.venv\Scripts\python.exe scripts/audit_sdk.py
```

По умолчанию используется каталог КОМПАС v25 Study; можно передать свой Bin-каталог аргументом. Генерируемые TLB-снимки остаются в `artifacts/sdk/`, вне Git. `scripts/example_plate_drawing.py` требует локальной модели, указанной в `SOURCE`; она не поставляется с репозиторием.

Открытая лицензия для проекта пока не выбрана; файл LICENSE не добавлен. КОМПАС-3D и его SDK принадлежат их правообладателям и не распространяются в этом репозитории.
